# Протокол эксперимента лабораторной № 1

Статус: реальные запуски ещё не выполнены. Пустые поля не являются результатами.

## Постоянные условия

- Groq, модель `openai/gpt-oss-20b`; фактически выбранная модель должна оставаться
  одинаковой во всех 12 запусках.
- Режим `/study`; точная системная инструкция из `app/prompts.py`.
- `LLM_REASONING_EFFORT=low`, `LLM_MAX_OUTPUT_TOKENS=2048`.
- Иные параметры случайности не передаются. История перед каждым запуском сбрасывается.
- Дата: заполнить после реального запуска.
- Запрос: «Объясни разницу между списком и множеством в Python. Ответ оформи
  четырьмя пунктами: порядок, дубликаты, проверка принадлежности, пример применения.
  Для каждого пункта дай одно короткое предложение.»
- Критерии до эксперимента: четыре пункта в указанном порядке; корректное различие
  дубликатов; корректная оценка сложности поиска; отсутствие ложного обещания
  упорядоченности множества; понятный пример.

Groq преобразует temperature 0 в 1e-8; ноль не гарантирует идентичные ответы.
Источник: https://console.groq.com/docs/openai

## Порядок

1. Запустить бот по README. Не менять конфигурацию во время серии.
2. Отправить `/study` и `/settings 0.0`.
3. Перед каждым из трёх одинаковых запросов отправить `/reset`, дождаться подтверждения.
4. Сохранить каждый полный ответ, длину, соблюдение формата и замечания.
5. Повторить для `/settings 0.3`, `0.7`, `1.0`: всего 12 ответов.
6. При 429 дождаться восстановления квоты; отдельно отметить отказ и успешный повтор.
7. Токены взять из `llm_usage` журнала, сопоставляя время и request ID.
   Если метрика отсутствует, записать «провайдер не предоставил».
8. Сравнить ответы внутри групп и между группами: повторяемость, структура, длина,
   соблюдение инструкции, неподтверждённые утверждения. Обосновать выбранную temperature.

## Улучшение инструкции

Дополнительные два запуска: неизменные модель, запрос и temperature 0.3.
Исходная неполная инструкция: «Ты помощник по программированию».
Улучшенная: текущий `PROMPTS['study']`, содержащий роль, задачу, формат и ограничения.
Для исходного запуска временно заменить только промпт `/study`, перезапустить бот,
выполнить `/reset`. Для улучшенного вернуть исходный код, перезапустить и снова
выполнить `/reset`. Сохранить оба ответа и точные инструкции, сравнить по тем же
заранее заданным признакам. После эксперимента вернуть сдаваемый промпт и прогнать тесты.

## Демонстрация

- Три режима и четыре значения temperature на действительной модели.
- Два отдельных Telegram-аккаунта с разными настройками и историями.
  Два устройства с одним аккаунтом не доказывают изоляцию.
- Перезапуск приложения и продолжение обоих диалогов.
- Reset и смена режима одного пользователя не затрагивают другого.
- Безопасное сообщение при отказе API и передача длинного ответа частями.
- Тесты, 12 ответов, анализ, собственный репозиторий.
- После всех проверок создать сдаваемый коммит и тег `lab1`.
